# ShopNexa — Render deployment

## Database
This build is configured to use the existing Render PostgreSQL service named `shopnexa-db`.

`render.yaml` sets:

- `DATABASE_URL` -> `shopnexa-db` connection string
- `WORK_AI_OWNER_MODE=true`
- writable `/tmp/shopnexa_data` only as a fallback for non-database files

Do **not** delete `shopnexa-db`.

## Required secrets in Render
Set these in the ShopNexa web service Environment page:

- `OWNER_PASSWORD`
- `MANAGER_PASSWORD`
- `EMPLOYEE_PASSWORD`
- `OPENAI_API_KEY` — required for Work AI image/video generation
- `TAVILY_API_KEY` — optional; DuckDuckGo is used as a no-key fallback
- `SECRET_KEY` — generated by Render
- `CREDENTIAL_RESET_TOKEN` — generated by Render

Never put an OpenAI key in GitHub, HTML, JavaScript, or this ZIP.

## Deploy
1. Put the contents of this ZIP at the root of the GitHub repository.
2. Commit and push.
3. In Render, make sure the `shopnexa` web service is connected to the repository.
4. Sync the Blueprint if you use `render.yaml`, or manually set `DATABASE_URL` to the **internal** connection string for `shopnexa-db`.
5. Trigger a new deploy.
6. Open `/health`. It should return a healthy response.
7. Sign in and test Products, Sales, Reports, Work AI, image generation and video generation.

## Important
The database connection is now the persistent store for users, products, sales, stock, expenses and activity. `/tmp` is not used as the primary database.

Generated Work AI media is stored on the web service filesystem. Render web-service filesystems are not a permanent media store, so generated media can disappear after a restart/redeploy. For permanent media, add object storage later.
